How the implied value is built

Every row is scored by one function, impliedValue in lib/model.ts, from the snapshot's own figures only — no protocol name is ever special-cased:

implied = TVL × 0.25 × growth × maturity × chains

  • TVL × 0.25 — the size of the activity a launch would price.
  • growth = 1 + clamp(7-day change, −50%, +150%) × 0.6 — momentum, for or against.
  • maturity = 0.6 + min(age in days, 1095) / 1095 × 0.4 — how long it has run with no token recorded; unknown age counts as 365 days.
  • chains = 1 + 0.03 × min(chain count, 6) — distribution across chains, capped.

“Pre-token” means the snapshot records no token for the protocol (no market cap, no CoinGecko id, no symbol). That is the record, not proof: a protocol on the list may still have a token its record does not carry. The board covers all 40 watchlist protocols, then every other rankable pre-token protocol in the snapshot. Protocols whose token already trades are set apart in the Live tokens tab at the market's own value — never mixed into the ranking. An implied value is this radar's own claim, not a prediction that a token will be issued, or when.

Source: DefiLlama protocol snapshot, as of . Farm steps name a cost and a time each; never pay to claim, and claim only from a link the protocol itself publishes.
